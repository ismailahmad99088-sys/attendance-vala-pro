==================================================

1. NO FAKE API.
2. NO FAKE DATABASE.
3. NO MOCK BACKEND.
4. NO HARDCODED PRODUCTION ATTENDANCE DATA.
5. NO FAKE LIVE STATUS.
6. NO FAKE GPS LOCATION.
7. NO FAKE DEVICE/BIOMETRIC RESPONSE.
8. NO localStorage/sessionStorage as a replacement for database persistence.
9. Use the existing Software Vala authentication, database, backend and UI architecture wherever available.
10. Before creating anything, inspect the existing repository and reuse existing components/services/tables.
11. Do not create duplicate components, duplicate APIs or duplicate database systems.
12. Use realistic seed data ONLY for the demo/testing environment.
13. Clearly distinguish seed/demo records from future real attendance records.
14. Every dashboard number must come from the real database.
15. Every attendance action must create/update a real persisted record.
16. Server-side authentication and authorization are mandatory.
17. Attendance timestamps must be generated by the trusted backend/server wherever possible.
18. Never allow the frontend to arbitrarily submit a fake attendance timestamp.
19. Never show a person as PRESENT unless a valid attendance event exists.
20. Never show a person as CHECKED OUT unless a valid checkout event exists.
